# PM-01: Product Strategy & Vision

## Product Vision Board (Pichler 2016)
| Section | Content |
|:---|:---|
| **Vision** | Ultimate purpose/change the product creates |
| **Target Group** | Who benefits most |
| **Needs** | Main problem/benefit addressed |
| **Product** | Key features/standout qualities |
| **Business Goals** | Revenue, market share, cost savings |

## DHM Model (Biddle — Netflix)
Three questions for every strategy initiative:
1. **D**elight customers — Does this make users love the product?
2. **H**ard to copy — Is this defensible? (technology, data, network effects, brand)
3. **M**argin enhancing — Does this improve unit economics?
Also: **GLEe** (Get big on X, Lead Y, Expand to Z) and **GEM** (Growth, Engagement, Monetization) for roadmap prioritization.

## Product-Market Fit
| Method | Author | How |
|:---|:---|:---|
| **40% Test** | Ellis | "Very disappointed" ≥40% = PMF |
| **Superhuman Engine** | Vohra | Segment users → analyze "very disappointed" → build roadmap 50/50 (delight fans / convert fence-sitters) |
| **Retention Curve** | Chen | If curve flattens above 0%, you have PMF |
| **Leading Indicators** | Andreessen | "Product being pulled out of your hands" |

## Jobs-to-be-Done (JTBD)
| Framework | Author | Focus |
|:---|:---|:---|
| **Outcome-Driven Innovation** | Ulwick | Quantitative: desired outcomes as measurable statements |
| **Competing Against Luck** | Christensen | Qualitative: "hiring" products for functional/emotional/social jobs |
| **Switch Interviews** | Klement | Forces of progress: push/pull/anxiety/habit driving switching |

## 7 Powers (Helmer 2016)
Scale Economies, Network Economies, Counter-Positioning, Switching Costs, Branding, Cornered Resource, Process Power

# PM-02: Product Discovery & Validation

## Opportunity Solution Tree (Torres 2021)
```
Desired Outcome (OKR Key Result)
├── Opportunity 1 (customer need/pain/desire)
│   ├── Solution A → Assumption Test
│   └── Solution B → Assumption Test
├── Opportunity 2
│   ├── Solution C → Experiment
│   └── Solution D → Prototype Test
```
Weekly: interview customers, update tree, run assumption tests.

## Four Risks (Cagan)
| Risk | Question | Test Method |
|:---|:---|:---|
| **Value** | Will customers buy/use it? | Customer interviews, fake door |
| **Usability** | Can users figure it out? | Prototype testing |
| **Feasibility** | Can we build it? | Tech spike, feasibility prototype |
| **Business Viability** | Does it work for the business? | Stakeholder alignment |

## MVP Types (Ries, Savoia)
| Type | Description | Best For |
|:---|:---|:---|
| **Concierge** | Manual service mimicking product | Complex workflows |
| **Wizard of Oz** | Human behind automated facade | AI/automation features |
| **Fake Door** | Link/button to nonexistent feature | Demand validation |
| **Landing Page** | Sales page before product exists | Market interest |
| **Pretotype** (Savoia) | Test initial appeal before building | Any new concept |

## Design Sprint (Knapp — 5 days)
Monday: Map → Tuesday: Sketch → Wednesday: Decide → Thursday: Prototype → Friday: Test

# PM-03: Roadmapping & Planning

## NOW/NEXT/LATER Roadmap (Bastow/ProdPad)
| Column | Certainty | Time Horizon | Content |
|:---|:---|:---|:---|
| **NOW** | High — committed | Current quarter | Defined problems with solutions in progress |
| **NEXT** | Medium — planned | Next quarter | Validated problems with candidate solutions |
| **LATER** | Low — exploring | Future | Opportunities being researched |

## OKR Structure (Doerr/Wodtke)
**Objective**: Qualitative, inspiring, time-bound (What do we want to achieve?)
**Key Results** (3-5): Quantitative, measurable, evidence of progress (How do we know we've achieved it?)
Rhythm: Quarterly set → Weekly check-in → Quarterly review
Scoring: 0.0-1.0 (0.7 = target; 1.0 = sandbagging)

## PR/FAQ (Amazon Working Backwards)
| Section | Content |
|:---|:---|
| **Press Release** | Headline, subheading, problem, solution, quote from leader, how it works, customer quote, CTA |
| **External FAQ** | Customer questions: pricing, availability, migration |
| **Internal FAQ** | Business questions: TAM, P&L, dependencies, timeline, risks |

## GIST Framework (Gilad)
**G**oals (outcome metrics) → **I**deas (hypotheses, not commitments) → **S**teps (experiments) → **T**asks (execution)

# PM-04: Prioritization Frameworks

## RICE Scoring (Intercom)
**Score = (Reach × Impact × Confidence) / Effort**
| Factor | Scale | Notes |
|:---|:---|:---|
| Reach | # of people/events per quarter | Quantified users affected |
| Impact | 0.25 / 0.5 / 1 / 2 / 3 | Minimal to Massive |
| Confidence | 50% / 80% / 100% | Based on evidence quality |
| Effort | Person-months | Engineering + design time |

## Cost of Delay (Reinertsen 2009)
**WSJF = Cost of Delay / Job Duration**
CoD = User-Business Value + Time Criticality + Risk Reduction/Opportunity Enablement
Key insight: "If you only quantify one thing, quantify the cost of delay."

## Kano Model Categories
| Category | Present | Absent | Strategy |
|:---|:---|:---|:---|
| **Must-Be** | No satisfaction | Dissatisfaction | Must have — table stakes |
| **One-Dimensional** | Satisfaction ↑ | Dissatisfaction ↑ | More is better |
| **Attractive** | Delight | Neutral | Differentiation opportunity |
| **Indifferent** | Neutral | Neutral | Don't build |

## Confidence Meter (Gilad)
| Evidence Type | Confidence Score |
|:---|:---|
| Gut feeling / opinion | 0.01 |
| Anecdotal data | 0.1 |
| Market data / research | 1.0 |
| Validated with users | 5.0 |
| A/B test result | 10.0 |

# PM-05: User Research & Personas

## Goal-Directed Persona (Cooper)
| Section | Content |
|:---|:---|
| Photo + Name | Humanize the archetype |
| Demographics | Age, role, location, tech comfort |
| Goals | What they're trying to achieve |
| Frustrations | Current pain points |
| Behaviors | How they currently solve the problem |
| Scenario | Day-in-the-life context |
| Quote | Captures their mindset |

## 5 Rings of Buying Insight (Revella)
1. **Priority Initiatives** — What triggers the buying process?
2. **Success Factors** — What outcomes do they expect?
3. **Perceived Barriers** — What concerns do they have?
4. **Decision Criteria** — How do they evaluate options?
5. **Buyer's Journey** — Who/what influences decisions?

## Empathy Map (Gray/XPLANE)
| Quadrant | Content |
|:---|:---|
| **Says** | Direct quotes from interviews |
| **Thinks** | Internal thoughts (may differ from says) |
| **Does** | Observable actions and behaviors |
| **Feels** | Emotional state and concerns |
| **Pains** | Frustrations, obstacles, risks |
| **Gains** | Wants, needs, measures of success |

## Customer Journey Map Structure
Stages → Actions → Touchpoints → Thoughts → Emotions → Pain Points → Opportunities
